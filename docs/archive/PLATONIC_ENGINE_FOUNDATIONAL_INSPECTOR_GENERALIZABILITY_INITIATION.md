## 1. What PlatonicEngine is

PlatonicEngine is a geometric-semantic transformation workspace.

It begins with polyhedra, but its real subject is not rendering solids. Its subject is how generated worlds remain intelligible after transformation.

A vertex is not only a point. It may become:

```txt
a named conceptual dwelling;
a packet carrier;
a source;
a generated child;
a dual counterpart;
a semantic projection;
a trace participant;
a carrier-bearing node in a field;
a future support in a topological process.
```

An operation is not only a mesh rewrite. It is a transformation event that should preserve enough structure for later inspection:

```txt
what existed before;
what was generated;
what became a child;
what relation produced it;
what field it enters;
what ambiguity remains;
what later semantic or topological process may inherit.
```

The long-term project is not merely a polyhedral app. It is an attempt to build a workspace where:

```txt
geometry
+ generation
+ sourcehood
+ field behavior
+ local birth grammar
+ conceptual naming
+ later topology
```

can fold into a single framework of intelligible transformation.

The human’s intended use is roughly:

```txt
Place primal concepts on a seed shape.
Apply geometric generation such as Ambo.
Receive generated sites.
Read their lineage, field, and local birth-law.
Use those readings to name what can dwell there.
Repeat across generations.
Eventually produce material for a topological life-of-concepts workspace.
```

That is the ambition. The present crisis concerns whether the field layer can carry that ambition.

## 2. Brief history of the project

This section is deliberately compressed but broad. You should know how the project reached the current crisis.

### 2.1 Shape and Ambo foundation

The first stable layer was geometric.

PlatonicEngine began as a browser app for recursive Ambo / rectification on convex polyhedral forms. The shape layer contains:

```txt
vertices
edges
faces
cells
generation history
lineage
source operations
residue/core distinction
selection and inspection state
```

Ambo Dissection creates generated midpoint vertices and new cell structures. This established the basic idea that geometry produces **children** whose lineage must remain inspectable.

This layer remains the base. It should not be confused with field, semantics, or topology.

### 2.2 Packets and concept-bearing vertices

The project then treated primal vertices as possible conceptual dwellings. Packet editing remained centered on primal vertices. Later semantic expansion was not allowed to silently mutate every entity into a packet carrier.

This distinction matters: a generated site may eventually host a concept, but not every derived artifact is automatically a semantic packet.

### 2.3 Early field layer and the first trap

The field layer was originally intended as a derived interference atlas over a source-domain. Vertices, including generated child vertices, should become sources. The field should eventually help read reinforcement, cancellation, routes, gates, loops, regions, supports, and other constraints.

The first field branch produced a large amount of infrastructure:

```txt
source domains
closed-surface sampling
complex superposition
intensity and phase
contribution ratios
feature candidates
route/gate candidates
support/region candidates
evidence stability
view models
UI exposure
```

This became dangerous. The field became technically substantial before becoming humanly fruitful. It produced diagnostics and caveats but did not help the human name generated sites. This led to the **Event Legibility Pivot**.

### 2.4 Event Legibility Pivot

The pivot law became:

```txt
event legibility before field expansion
```

The generated site became the center. The field lost sovereignty. The field should appear as a witness around a generated site, not as a cockpit of internal diagnostics.

The proving event became:

```txt
named/profile-assigned tetrahedron
→ one Ambo
→ six generated midpoint children
→ generated-site readings
→ human naming attempt
```

This was explicitly not the general field layer.

### 2.5 FieldCue and generated-site reading

A FieldCue target contract was written. It preserved the human’s ambitious field-cue horizon:

```txt
child-source inheritance
field-world participation
routes
gates
loops
vortices
regions
supports
phase transformations
visual/interference behavior
naming pressure
```

But FieldCueV0 remained narrow and one-event-bound.

GeneratedSiteReadingV0 was then created as the folded human-facing object, with the field-cue as the field witness inside it.

However, UI work became another problem. At one point, panels exposed too much “this is not semantic naming / not topology / not final meaning” language. That was a symptom that internals were being rendered as product UI. This should remain a warning for future work: a UI full of epistemic caveats is not necessarily a usable interface.

### 2.6 Source-signature crisis

The next crisis was source meaning.

The early profile-aware field stack could generate source emissions, but the active fixture was too weak: amplitude, wave number, and attenuation were invariant; phase carried too much; children could collapse or fall back. The system could display numbers without making them earned source signatures.

This led to finite profile systems, Quark child inheritance, and then the stronger law:

```txt
source signature = structured source state
emitted tuple    = field-facing reduction of that state
```

The emitted tuple is necessary because the existing atlas consumes:

```txt
amplitude
waveNumber
phase
attenuation
```

but the tuple is not the whole source signature.

### 2.7 Structured source-state crisis

A structured source-state regime was introduced for the one-Ambo tetrahedron event. It encoded edge states, complement/antipodal axes, orientation/polarity conventions, harmonic components, and tuple-reduction honesty.

A key test passed:

```txt
R4-S1 made antipodality recoverable from anonymized emitted tuples.
```

A stronger test failed:

```txt
R4-S1 did not make antipodality recoverable from raw field behavior under the existing propagation law.
```

This revealed that structure can be present in source-state and visible in emitted tuple, yet fail to appear as recoverable field behavior after propagation.

### 2.8 Fano-octonionic turn

The project then took a deeper route.

Rather than treating source state as merely scalar tuple plus metadata, it introduced a Fano-octonionic local carrier model for the tetrahedral first-birth event.

This produced the current C0→G0 chain:

```txt
C0-R1 — strict Fano carrier assignment and antipodal quotient
C1    — local carrier channel table
A0    — associator / projection displacement table
E0    — finite harmonic primal emission profile library
E1    — child emission envelope table
F0    — carrier graph projection law model card
F1    — carrier graph field table
F2    — continuous spatial support projection table
G0    — generational field update table
```

This chain is now the immediate background of the current crisis.

## 3. What the C0→G0 chain has built

The C0→G0 stack should be treated as real evidence, not as doctrine.

### 3.1 C0-R1 — strict carrier table

The accepted primal carrier assignment is:

```txt
A = e1
B = e2
C = e4
D = e7
```

The six first-born child carriers arise from ordered Fano products:

```txt
M_AB: A·B = +e3
M_CD: D·C = -e3

M_AC: A·C = +e5
M_BD: B·D = -e5

M_AD: A·D = +e6
M_BC: C·B = -e6
```

The correct complement structure is:

```txt
M_AB / M_CD → ray:e3, opposite signed lifts
M_AC / M_BD → ray:e5, opposite signed lifts
M_AD / M_BC → ray:e6, opposite signed lifts
```

The crucial repair was that antipodality is not a hand map and not a root-A filter. It is derived from all ordered lifts, quotiented into carrier-ray groups, then represented by selected canonical display pairs.

### 3.2 C1 — local carrier channels

C1 derives local carrier channels.

Each child carrier can act with a source carrier to recover another source carrier. These channels include:

```txt
parent-return channels;
projection-loop channels.
```

They are carrier operations, not semantic labels. They are response kernels, not emissions yet.

### 3.3 A0 — associator / projection displacement

A0 separates:

```txt
formal associator:
  (J·P)·Q versus J·(P·Q)

canonical projection displacement:
  (J·P)·Q versus J·q_child
```

This matters because octonion nonassociativity is not a nuisance. It warns that deeper generation cannot freely reassociate paths.

A0 does not solve recursion. It exposes the residue/displacement structure of the first local carrier world.

### 3.4 E0 — harmonic emission profile library

E0 adds oscillator emissions to carriers.

The working source definition becomes:

```txt
source = carrier + oscillator emission profile
```

E0 defines three finite profile families:

```txt
equal-phase-quadrature-control-v0
just-intonation-tetrad-v0
pythagorean-tetrad-v0
```

These are finite libraries, not arbitrary tuning.

### 3.5 E1 — child emission envelopes

E1 builds child emission envelopes from C1 channels and E0 profiles.

Each child has:

```txt
intrinsic birth emission
+ local channel-response kernels
```

Important distinction:

```txt
intrinsic birth emission = free emission
local channels = available response kernels, not always-on emissions
```

### 3.6 F1 — carrier graph field

F1 builds a carrier-connection graph.

It includes:

```txt
primal-source nodes
child-source nodes
birth edges
parent-return response edges
projection-loop response edges
complement-coupling response edges
carrier transport rows
activation weights
path-sum readiness rows
spatial support placeholders
```

F1-R1 repaired a serious failure: complement transport must preserve signed antipodality, not flatten both children into the same unsigned carrier ray.

### 3.7 F2 — continuous spatial support projection

F2 assigns a centered tetrahedral coordinate frame:

```txt
A = ( 1,  1,  1)
B = ( 1, -1, -1)
C = (-1,  1, -1)
D = (-1, -1,  1)
```

Then child midpoints become octahedral axes:

```txt
M_AB = ( 1,  0,  0)
M_CD = (-1,  0,  0)

M_AC = ( 0,  1,  0)
M_BD = ( 0, -1,  0)

M_AD = ( 0,  0,  1)
M_BC = ( 0,  0, -1)
```

F2 gives the local graph continuous spatial supports and sampleable field contribution rows. Carrier state remains upstream and is not reduced to phase. Complex coefficients are field observables, not source ontology.

### 3.8 G0 — generational field update

G0 proves the first generation update:

```txt
G0:
  active sources = A, B, C, D
  active graph edges = none
  baseline = primal node contributions

G1:
  active sources = A, B, C, D plus six child sources
  graph edges = first-birth carrier graph
  baseline = primal + child intrinsic node emissions
```

The key verified identity:

```txt
baselineField(G1) - baselineField(G0)
=
sum of born child source baseline contributions
```

G0 does not invent G2. It does not compute semantics. It does not attach Trison. It does not build UI.

## 7. The carrier assignment problem

The central problem is:

```txt
Given a shape and its generated sites,
what algebraic carrier does each source receive,
and why that carrier rather than another?
```

For the tetra first-birth case, we have a special answer:

```txt
A = e1
B = e2
C = e4
D = e7
```

and first-born child carriers follow by ordered products.

But for another shape, even the first step is unclear.

Example: cube.

A cube has:

```txt
8 vertices
12 edges
```

The octonion imaginary basis has:

```txt
7 units
```

So immediate questions appear:

```txt
What carrier does the 8th vertex get?
Can the real unit 1 be used?
Can a unit be reused?
Does reuse collapse distinct sources?
Should carriers be local rather than global?
Is a larger algebra required?
Are carriers attached to vertices, edges, faces, or local charts?
```

For deeper Ambo generations, the problem intensifies:

```txt
What counts as a parent relation?
Which carrier operation corresponds to that relation?
Which bracketing is used?
When is nonassociativity signal?
When is it obstruction?
When do two carrier paths identify the same source?
When do they remain distinct due to genealogy?
```

Until this carrier assignment problem is solved or bounded, the field layer is not general.
