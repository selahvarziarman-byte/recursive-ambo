The crucial repair in C0-R1 was that antipodality is not a hand map and not a root-A filter. It is derived from all ordered lifts, quotiented into carrier-ray groups, then represented by selected canonical display pairs.


This is not antipodal. The antipodal lift for `A·B = +e3` is `D·C = -e3`.

C1 established that local channels are real carrier operations, not semantic labels.

It also established that response channels are not emissions yet. They become available kernels downstream.

## 6. The carrier assignment problem

The carrier assignment problem is:

```txt
Given a shape and its generated sites,
what algebraic carrier does each source receive,
and why that carrier rather than another?
```

For the current tetra case, the answer was:

```txt
A = e1
B = e2
C = e4
D = e7
```

Then child carriers followed from ordered products:

```txt
M_AB = A·B = +e3
M_CD = D·C = -e3

M_AC = A·C = +e5
M_BD = B·D = -e5

M_AD = A·D = +e6
M_BC = C·B = -e6
```

This worked because the tetrahedron has:

```txt
4 vertices
6 edges
3 opposite edge-pairs
```

and the Fano assignment was selected so those edge-pairs become:

```txt
same ray + opposite sign
```

For other shapes this is not automatically true.

Example: cube.

A cube has:

```txt
8 vertices
12 edges
```

The octonion imaginary basis has only seven units:

```txt
e1, e2, e3, e4, e5, e6, e7
```

So if cube vertices are primal sources, questions appear immediately:

```txt
What carrier does the 8th vertex get?
Can the real unit 1 be used?
Can an imaginary unit be reused?
Does reuse collapse distinct vertices?
Is a larger algebra required?
Does the algebra need to be local rather than global?
```

At the edge level:

```txt
12 cube edges → what child carriers?
```

The tetra case had:

```txt
6 edges → 3 signed rays
```

A cube might require:

```txt
12 edges → 6 signed rays
or 12 distinct carriers
or repeated carrier classes
or face-local carrier charts
or a graph-local carrier system
```

None of that follows from the current code.

For deeper ambo generations the problem intensifies.

A second-generation source might arise from:

```txt
child-child relation
primal-child relation
edge of the rectified cell
face relation
some new local geometry
```

If a new source combines two child carriers, e.g.

```txt
M_AB = +e3
M_AC = +e5
```

one might try:

```txt
(+e3)·(+e5)
```

But this is not automatically legitimate. It depends on the geometric birth relation, and octonion nonassociativity makes the path and bracketing meaningful.

Example:

```txt
(A·B)·C
```

need not equal:

```txt
A·(B·C)
```

So deeper generation requires a policy for:

```txt
what counts as parent relation;
which carrier operation corresponds to the relation;
what bracketing is used;
when two birth paths identify the same source;
when different paths remain different source histories;
when carrier collisions are meaningful;
when carrier collisions are failures.
```

Until that policy exists, the carrier layer is not general.

