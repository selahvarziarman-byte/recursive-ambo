# 0005 — The engine produces structural semantics; "semantic identity" is the user's mirror (no linguistic semantic layer)

The framework's sole end is to be a **prosthesis for thinking**. The engine produces **structural content, which *is* the semantics** — there is only **structural identity** (`scope × lineage`). **Semantic identity** is not a second thing the engine computes; it is the **mirror** of the structural content in the mind of the user (or any agent using the framework).

## The bloat this corrects

The prevailing framing treated the "semantic layer" as an engine stage that mints **linguistic** content — names, meanings — downstream of the module. That is a bloat. The engine never mints names; it delivers honest structure for the user's mind to mirror as meaning. This is a finding for the mothership: it corrects the docs'/readings' "semantic layer assigns names" framing.

## Consequences

- The "identity overload" dissolves by **relocation**: inside the framework, "identity" means **structural identity**, full stop; **identification** is the structural gluing event; **semantic identity** names the user's mirror and lives *outside* the engine.
- The cardinal law "co-location ≠ identity" reads: the engine's structural co-location (an identification) does **not** dictate the user's mirrored judgment of sameness. The engine's duty is *honest structure* so the mirror is trustworthy — which is *why* the faithfulness/honesty discipline exists (don't feed the mirror lies; Vital-Note §16).
- A **name** is the user's mirror-label, never an engine output (a packet `label` is inert pass-through).
- The module's deliverable (the atomic + systemic trace) **is** the structural semantics the user mirrors; the engine's job ends at delivering it honestly.
