# Amendment to the Field Source Profile and Quark-Coherent Child Inheritance Contract
## Structured Source-State and Tuple-Reduction Amendment

Audience: future agents, planners, prompt-writers, Codex workers, auditors, and any lieutenant working on PlatonicEngine’s field source-profile, field-cue, or generated-site legibility layers.

Status: contract amendment. This document does not replace the Field Source Profile and Quark-Coherent Child Inheritance Contract v0.2. It amends and sharpens it after the scalar source-regime failure and the structured source-state report.

Authority: binding within the current Event Legibility Pivot. Use this amendment wherever the older source-profile contract could be misread as equating a source signature with its emitted scalar tuple.

---

## 0. Reason for amendment

The original source-profile contract correctly established that:

```txt
A field source is not a free numeric emitter.
Primal source profiles come from a finite generated profile system.
The human assigns primal vertices to generated profile slots.
Generated midpoint children inherit through Quark-coherent grammar.
A tetrahedral Ambo child must retain parent edge, complement edge, antipodal child, Quark channels, ratio constants, derivation record, and degeneracy diagnostics.
The numeric emission tuple is only the reduced result of structured derivation.
The structure must not be erased.
```

The later source-signature crisis showed that this was still not explicit enough.

The implementation could satisfy much of the contract while still treating:

```txt
amplitude + waveNumber + phase + attenuation
```

as if that tuple were the full source signature.

That is now forbidden.

This amendment states the corrected law:

```txt
source signature = structured source state
emitted tuple    = field-facing reduction of that state
```

The tuple is necessary. It is not sovereign.

---

## 1. Amended core invariant

A field source is a source-domain vertex interpreted through a structured source state.

A source state may reduce to an emitted tuple for the current field atlas, but the emitted tuple is not identical with the source state.

For the current proving event:

```txt
source-domain vertex
→ structured source state
→ emitted tuple
→ field atlas contribution
→ field cue / generated-site reading
```

not:

```txt
source-domain vertex
→ emitted tuple as full source identity
```

The tuple may carry some structure in field-active form. It may reduce, compress, or lose other structure. The reduction must say which.

---

## 2. Definitions

### 2.1 Source-domain source

A source-domain source is still a vertex included in the active field source-domain.

Accepted sources include:

```txt
seed / primal vertices;
preserved vertices;
generated child vertices;
Ambo midpoint children.
```

Generated children must still enter the field source population when they belong to the active domain.

### 2.2 Structured source state

A structured source state is the real source signature.

It carries, as applicable:

```txt
harmonic component;
structural / representation component;
derivation component;
tuple-reduction component;
provenance;
policy and setup status;
unsupported / degenerate / fallback status.
```

### 2.3 Emitted tuple

An emitted tuple is the field-facing scalar projection consumed by the current field atlas:

```txt
amplitude;
waveNumber;
phase;
attenuation.
```

The emitted tuple is a reduction of the structured source state.

It is not the whole signature.

### 2.4 Reduction honesty

Reduction honesty is the requirement that every emitted tuple report what it preserves, compresses, leaves metadata-only, or loses.

A tuple that hides its reduction loss is invalid for FieldCueV0.


This is full algebraic seriousness inside the finite proving event.

It is not permission to build general-purpose exterior algebra, Clifford algebra, representation-theory infrastructure, all-shape source algebra, or a multi-component field engine.

The law is:


## 6. Structured source-state components

A v0 structured source state should be understood as containing four components.

### 6.1 Harmonic component

The harmonic component answers:

```txt
What does this source sing?
```

For v0 this may be:

```txt
kind = log-ratio-v0
ratio
logRatio
profileSystemId
profileSlotId
assignment provenance
```

The type should remain open enough that later regimes can replace scalar log-ratio with finite spectral packet, note-state, dyadic state, or chordal state.

### 6.2 Structural / representation component

The structural component answers:

```txt
Where does this source stand inside the tetrahedral Ambo grammar?
```

For v0 this includes:

```txt
primal vertex role;
edge / bivector child role;
endpoints;
complement edge;
antipodal child;
axis-pair;
orientation / polarity convention;
projection-source relation;
incidence relations needed by diagnostics.
```

### 6.3 Derivation component

The derivation component records how the state was produced.

For child states this includes:

```txt
source edge;
parent endpoint states;
projection states;
complement edge state;
antipodal state;
Quark channel records;
ratio constants;
common-mode harmonic inheritance;
differential structural polarity;
degeneracy / fallback / unsupported statuses.
```

### 6.4 Tuple-reduction component

The tuple-reduction component records how the structured state was projected into:

```txt
amplitude
waveNumber
phase
attenuation
```

It must report:

```txt
preserved structure;
reduced / compressed structure;
metadata-only structure;
lost structure;
reduction status.
```

## 7. Tuple-reduction law

The current field atlas remains scalar-tuple based.

The tuple reduction should initially follow this posture:

```txt
waveNumber:
  primarily harmonic component

phase:
  harmonic phase plus structural polarity projection, if the law is declared

amplitude:
  neutral in v0 unless a state-norm law is explicitly justified

attenuation:
  neutral / conservative in v0 unless a reach-locality law is explicitly justified
```

Structural polarity should first attempt to become field-active through phase/sign.

But it must be derived from the structural state.

The following is forbidden as a mere patch:

```txt
if child is antipodal, add π
```

The allowed form is:

```txt
define a source-state involution σ;
define a phase/sign projection π_phase;
audit that π_phase(σ(q)) has the declared relation to π_phase(q).
```

Example target relation:

```txt
π_phase(σ(q_child)) = π_phase(q_child) + π
```

or an equivalent relation under the declared v0 convention.

## 8. Required audits

Any implementation claiming this amendment must pass diagnostic audits equivalent to the following.

### 8.1 Finite system audit

```txt
no arbitrary tuple palette;
no free per-source sliders;
primal harmonic profiles generated from named finite system;
human assignment to slots preserved as provenance.
```

### 8.2 Structural capsule audit

```txt
four primal source states exist;
six generated edge source states exist;
edge endpoints are correct;
complement pairs are correct;
antipodal child links are correct;
orientation / polarity convention is declared;
incidence and projection relations are inspectable.
```

### 8.3 Antipodal covariance audit

For the complement operation:

```txt
c(AB)=CD
c(AC)=BD
c(AD)=BC
```

child derivation must satisfy a declared internal relation:

```txt
D(c(edge)) = σ(D(edge))
```

or an equivalent finite source-state covariance rule.

### 8.4 Structural covariance audit

Relabeling tetrahedron vertices must relabel source states coherently.

The regime must not depend on accidental array order, profile slot order, or display labels.

### 8.5 Tuple-reduction honesty audit

Every emitted tuple must report:

```txt
field-active structure;
reduced / compressed structure;
metadata-only structure;
lost structure;
neutral axes;
reduction status.
```

### 8.6 Unknown-feature retention audit

The source-state diagnostic must allow later inspection of relations not yet named by the human.

It should be possible to ask:

```txt
Which structural facts are present before reduction?
Which vanish after tuple projection?
Which children are distinct in state-space but equivalent after tuple projection?
Which facts became field-active?
Which remained derivation-only?
```

This audit prevents the project from adding one patch for every newly noticed feature.

### 8.7 Field-use audit

Before FieldCueV0 is trusted again, the system must be able to report:

```txt
what the child inherited harmonically;
what structural polarity it carries;
what was lost in tuple projection;
what field behavior followed after reduction;
whether the field witness is useful, weak, degenerate, or misleading-risk.
```

Where the original source-profile contract says or implies:

```txt
source signature = emitted profile / emitted tuple
```

this amendment overrides it.

```txt
source signature = structured source state
emitted profile / tuple = field-facing reduction
```

Where the original contract requires finite generated profile systems, Quark coherence, child-context preservation, complement edge, antipodal child, derivation records, degeneracy diagnostics, no free numeric emitters, no Shape mutation, no packet writing, and no semantic naming, it remains fully binding.

This amendment does not weaken those laws. It gives them the vessel they were missing.
