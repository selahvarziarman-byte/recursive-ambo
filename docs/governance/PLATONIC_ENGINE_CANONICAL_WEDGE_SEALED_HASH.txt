WHY IT EXISTS. `identifyOnComplex` — the general enactment behind every
multi-face sew, every re-sew, and the whole depth-4 generative closure — takes
its mode reference from `wedgeDirections(complex)`, which is FIRST-WRITER-WINS
over `complex.faces`. On an INTERIOR edge the two wedges traverse oppositely,
so the reference is whichever face happens to be listed first in the array.

MEASURED: rotating the faces array — a PURE RELABELLING, zero topological
content — yields TWO distinct merge partitions. On a shared-endpoint pair chi
MOVES (0 -> -1); on a disjoint-endpoint pair chi is BLIND and only the DEGREE
SEQUENCE separates the two objects. A shipped operation that is not a function
of its own input.

FREE edges have ONE wedge, hence no ambiguity — which is exactly why every
sealed surface (rims, sewBoundaryCircles, connectedSum, the depth-4 chain) was
never affected and nothing ever moved. The fix is NOT a sign change. It is:
"stop using array order as the reference where the wedge is ambiguous."

THE RULE (researcher, derived — not chosen):

    sigma = -s_A * s_B

  where s_X is the sign with which X's CANONICAL WEDGE traverses X's STORED
  arrow, and the CANONICAL WEDGE is the incident wedge on the face of SMALLEST
  COMMITTED FACE-ID — never by array position.

  Valence 1: the canonical wedge IS the only wedge -> reduces EXACTLY to the
    shipped free-edge rule. The free case FALLS OUT; it is not an exception.
    Free-edge behaviour must not move by one byte.
  Valence 2: every symmetric function of the wedge signs is CONSTANT
    (s1*s2 = -1, s1+s2 = 0), so orientation-compatibility carries ZERO
    information. The interior mode has NO orientation semantics: it is a

  THE FORM UNIFIES; THE MEANING DOES NOT. At valence 1 the rule is DERIVED. At
