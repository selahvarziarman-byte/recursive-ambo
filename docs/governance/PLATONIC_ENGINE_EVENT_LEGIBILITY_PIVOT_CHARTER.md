# PlatonicEngine Event Legibility Pivot Charter

Audience: future agents working with Arman on PlatonicEngine / recursive-ambo, especially any agent acting as mothership, planner, prompter, auditor, or architectural steward.

Status: strategic governance addendum. This is not a Codex prompt, not a backlog, not a UI plan, not a topology plan, and not an implementation contract. It is a binding correction to project direction after the field layer became technically substantial before becoming humanly fruitful or architecturally general.

## 0. Purpose of this charter

PlatonicEngine’s original aim remains intact: a generated geometric world should remain intelligible after transformation. Geometry, field, atomic grammar, semantic naming, and later topology are not meant to become rival systems. They are meant to fold into one framework of intelligible transformation.

The project has reached a danger point. The field layer has acquired a large amount of machinery: source profiles, Quark child inheritance, sampled atlases, candidate reports, evidence stability, view models, runtime boundaries, and UI exposure. Much of this work was necessary to prevent arbitrary source emission and decorative field rendering. But the field has not yet produced enough human fruit. It does not yet substantially help the human answer the central practical question:

> What concept can dwell at this generated site?

This charter exists to stop the field layer from consuming the project, and to prevent topology from becoming the next version of the same trap.

## 1. Corrected diagnosis

The current profile-aware field stack must be understood as an **event-bound field prototype**, not as the completed general field layer.

Its strongest current case is approximately:

```txt
named or profile-assigned tetrahedral seed
→ one Ambo event
→ six generated midpoint children
→ profile-aware source derivation
→ sampled field atlas and candidate reports
```

That is a serious prototype. It is not yet the general field layer promised by the larger project. It is not yet general across shapes, operations, selected local domains, arbitrary generations, or recursively named conceptual worlds.

Two failures must be corrected at once:

1. **Human-use failure**: the field computes and reports more than it helps the human name generated conceptual sites.
2. **Generality failure**: the implemented field behavior is still particular to one event, while project language has sometimes treated it as if it were already the general field stratum.

The hard pivot begins by naming this honestly.

## 2. New governing law

The new governing law is:

> Event legibility before field expansion.

No field-layer work is valid unless it does at least one of the following:

1. helps the human interpret a generated site in the current proving event; or
2. clarifies which parts of the current field machinery are general, event-specific, or unproven.

Work that does neither is frozen, even if it is mathematically interesting, visually attractive, or internally consistent.

The field layer is no longer allowed to justify itself by producing more infrastructure. It must now become useful inside the act of reading and naming generated sites.

## 3. The proving event

The near-term horizon is **one intelligible generation**:

```txt
four primal concepts inhabit the vertices of a tetrahedron
→ one Ambo operation generates new sites
→ the system helps the human read those generated sites
→ the human attempts to name what can dwell there
```

This event is not the whole project. It is the first proving ground where geometry, field, atomic birth-law, and human naming must actually fold together.

The proving event should not be treated as a general theory of all future shapes. It is a deliberate test case:

> Can PlatonicEngine help the human understand generated conceptual dwellings better than geometry alone?

If the answer is no, further field expansion is not justified.

## 4. The field loses sovereignty

The field is not the center of the project. The generated site is the center.

For the proving event, geometry, field, and atomic grammar serve as witnesses around the generated site:

```txt
Geometry says how the site was born.
Atomic grammar says what kind of birth-event may be present.
Field says what the active source-domain reinforces, cancels, mixes, blocks, tensions, or leaves ambiguous.
The human names, rejects, suspends, or revises the concept that may dwell there.
```

The field must appear to the human only as interpretive pressure, not as an autonomous cockpit of internal machinery.

This charter does not define the minute format of field cues, generated-site readings, or naming panels. Those details belong to the human and the relevant lieutenant when implementation is actually scoped. The mothership-level requirement is only this:

> Field output must be compressed into something that helps the human read a generated site.

Raw field machinery is not itself fruit.

## 5. Generated-site reading

The central folded object of the pivot is the **generated-site reading**.

A generated-site reading is not a packet, not a topology mark, not a semantic truth claim, not a field report, and not a final ontology entry.

It is a human-facing interpretive object that gathers, at a high level:

```txt
what generated this site;
what relations make the site structurally distinct;
what field pressure is relevant, if any;
what atomic birth-law is relevant, if any;
what ambiguity or degeneracy must not be hidden;
what question the human must answer in order to name it.
```

A generated-site reading must preserve semantic honesty. It may support naming, but it must not auto-name. It may expose pressure, but it must not declare meaning. It may record human decisions, but it must not silently write them into packets or shape history.

## 6. Field triage

All existing and future field artifacts must be classified into one of three categories.

### 6.1 Probably general

These are field principles that appear aligned with the larger project:

```txt
source-domain;
source population;
generated children entering the source population;
closed-geometry computation;
complex superposition;
separation of intensity, phase, and contribution mixture;
explicit source policy;
policy relativity;
bounded derived reports;
unsupported / degenerate states.
```

These may remain part of the long-term field definition, but they still must prove usefulness in the proving event.

### 6.2 Event-specific but possibly abstractable

These belong first to the current tetrahedral Ambo event:

```txt
six midpoint children;
edge-complement pairings;
antipodal child structure;
tetrahedral Quark inheritance;
four-channel child derivation;
current profile-aware runtime support boundaries.
```

Agents must not treat these as already-general field architecture. They are powerful local grammar, not universal law until proven portable.

### 6.3 Unproven as human fruit

These include higher-order candidate structures such as:

```txt
routes;
gates;
loops;
regions;
support classes;
vortices;
feature clusters;
evidence-stability taxonomies;
marker overlays whose main value is internal inspection.
```

These are not rejected. They are demoted. They may be used only if they help a generated-site reading. No new families in this class may be added during the pivot.

## 7. Moratorium on field expansion

Until the proving event becomes humanly legible, the following are frozen:

```txt
new field candidate families;
new route/gate/support/region taxonomies;
new field visual sophistication;
new stability bureaucracy;
new source-profile variants unless directly required for the proving event;
general-shape field expansion;
deeper-generation field expansion;
multi-shape field work;
field-to-topology export;
field persistence;
source-profile editing UI as a general product surface.
```

Allowed work is limited to:

```txt
making the proving event legible to the human;
compressing existing field output into generated-site readings;
showing when existing field output is useless, saturated, degenerate, or misleading;
clarifying which field assumptions are general and which are event-bound.
```

This is a moratorium, not a deletion. Existing machinery may be reused. It may not be allowed to set the agenda.

## 8. Generality audit

Before any attempt to generalize the field layer beyond the current event, the project must perform a generality audit.

The audit must answer:

```txt
Which parts of the current field stack are universal field laws?
Which parts are tetrahedral-Ambo local grammar?
Which parts are artifacts of the current source-profile fixture?
Which parts are only diagnostic scaffolding?
Which parts actually help the human read generated sites?
Which parts should be hidden, compressed, or removed from normal attention?
```

The audit should not become another certification bureaucracy. It exists to prevent a particular event-bound prototype from masquerading as the general field layer.

Only after this audit, and only after the proving event has borne fruit, may the project choose one portability test.

A portability test must be singular and bounded, for example:

```txt
same seed, one deeper generation;
different seed, same operation;
same generated-site reading idea, different local domain.
```

The project must not jump from one-Ambo tetrahedron to general field universality.

## 9. Topology discipline

Topology remains important, but it must not become the next avoidance trap.

The project does not currently need a monster topology program. It does not need a general topology workspace, a quotient engine, a topology UI, a surface playground, or a full theory of semantic fibers in order to survive the present crisis.

For now, topology has only one governing function:

> It reminds the project that named material must preserve provenance, ambiguity, relation, and transformation history so that it can later be moved into another process space without false identity claims.

Near-term topology work is therefore forbidden unless the proving event has already produced named generated material that raises a concrete topological question.

Topology must not be used to postpone the current task. The project must not say:

```txt
We cannot make generated sites useful until topology is modeled.
```

That is the same error as saying:

```txt
We cannot make the field useful until the field is fully general.
```

The anti-monster rule for topology is:

> No topology branch may begin from general capability. It must begin from a named-material pressure produced by an intelligible generated event.

When topology eventually starts, its first proof must be small, bounded, and human-motivated. It must preserve the distinction between support, co-location, identity, fusion, conflict, and rejection. It must not mutate source shape history by default. It must not become a freeform topological universe before there is named material worth transforming.

## 10. Atomic discipline

The atomic layer should help read generated child-events, but it must not become a second field trap.

For the proving event, atomic grammar is a witness, not a sovereign subsystem. It may tell the human what kind of birth-event is present. It may help distinguish mediation, projection, complement, antipode, or other local grammar. It must not auto-name. It must not expand into a full workspace before the proving event shows durable value.

Atomic work is permitted only insofar as it helps generated-site readings or clarifies local birth-law already present in the proving event.

## 11. Human naming loop

The human act is central.

The intended use is:

```txt
The human assigns or invokes primal concepts at the seed vertices.
The operation generates new conceptual dwellings.
The system presents readings of those dwellings.
The human names, rejects, suspends, or revises possible concepts for those dwellings.
The named generation becomes material for later work.
```

The system may assist by exposing structure, pressure, contrast, ambiguity, and warnings. It may not replace the human act of conceptual judgment.

A generated name should begin as a human assignment with status, not as an automatic packet truth.

## 12. Branch permission test

Before any new branch, feature, report, UI, or document is approved, the planner or mothership must answer:

```txt
Does this help the human read a generated site in the proving event?
Does this clarify the gap between event-bound field behavior and general field law?
Does this avoid new field candidate expansion?
Does this avoid topology as a substitute for current fruit?
Does this preserve semantic honesty and human naming authority?
Does this keep derived layers derived and source shape history untouched?
Can its value be stated without referencing internal diagnostic abundance?
```

If the answer to the first two questions is no, the work is not part of the pivot.

## 13. Success criteria

The pivot succeeds when the project can honestly say:

```txt
A human can place four primal concepts on a tetrahedron.
After one Ambo, the generated sites become legible enough to support naming attempts.
The system shows why a site is structurally distinct.
The field contributes useful pressure or honestly reports when it does not.
Atomic birth-law contributes useful context or honestly reports when it does not.
Ambiguity, degeneracy, and unsupported cases are visible.
The human can record naming decisions without those decisions becoming false automatic truth.
```

The decisive question is not:

```txt
How many field candidates exist?
```

The decisive question is:

```txt
Does the generated event let the human understand something they could not understand before?
```

## 14. Governance precedence

This charter does not replace the Ground Plan. It protects the Ground Plan from cost leakage.

This charter does not repeal the Field Layer Appendix. It prevents the appendix from being misread as permission for unlimited field expansion.

This charter does not repeal the Field Source Profile / Quark-Coherent Child Inheritance Contract. It prevents source-profile rigor from becoming another reason to delay human usefulness.

This charter supersedes stale handoffs that recommend further field-stack growth unless that growth directly serves event legibility or the generality audit.

The repository remains the authority for actual implemented state. This charter governs strategic permission, not factual claims about what the repo currently contains.

## 15. Forbidden interpretations

The following interpretations are forbidden:

```txt
The current profile-aware field stack is already the general field layer.
More field infrastructure is automatically progress.
Topology must be modeled before generated sites can become useful.
Model-first means indefinite model construction without human fruit.
Candidate routes, gates, regions, or supports are already semantic structures.
Field output can name concepts.
Atomic grammar can name concepts.
Human naming decisions can silently become packet truth.
A future workspace named in the Ground Plan is automatically a near-term task.
A possible topology idea is automatically an implementation mandate.
```

## 16. Compact binding statement

PlatonicEngine now enters the Event Legibility Pivot.

The field layer has enough machinery to become useful, but only if it is subordinated to generated-site reading. The current profile-aware field stack is an event-bound prototype, not the completed general field layer. The first proving event is a named tetrahedron undergoing one Ambo generation. The project must make that event humanly legible before expanding the field, building topology, or adding new candidate taxonomies.

Field, atomic grammar, and later topology remain part of the universal horizon. None of them may become a monster that postpones the human act of understanding what concept can dwell at a generated site.
